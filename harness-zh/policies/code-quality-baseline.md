# 企业级代码质量强制基线

本文件定义技术栈无关的最小要求。规则 ID、阻断等级、验证方式和例外策略以 `rules/registry.yaml` 为准。技术栈适配规则只能加严，不能降低本基线。

## 1. 安全与身份

- `SEC-001`、`SEC-002`：不得硬编码或提交秘密、生产凭证、真实个人数据、未允许的构建产物和敏感日志。
- `SEC-003`：不得绕过认证、授权、限流、审计、反滥用控制或平台条款。
- `SEC-004` 至 `SEC-008`：秘密必须受控存储；受保护资源同时校验身份和资源权限；敏感状态变更可审计；对外错误脱敏；涉及受监管数据时完成隐私审查。

## 2. 数据与外部边界

- `DATA-001` 至 `DATA-008`：测试和文档只使用脱敏/合成数据；查询采用参数绑定；动态标识符白名单映射；迁移具备兼容、回滚、备份和审批；大查询必须有资源边界。
- `BOUND-001` 至 `BOUND-007`：外部输入、上传文件、URL 和跨域来源均需校验或 allowlist；网络调用具备超时、取消和有限重试；禁止 Shell 拼接、动态代码执行和失败伪装成功。

## 3. 架构与 API

- `ARCH-001` 至 `ARCH-008`：组合优先于继承；抽象须有真实边界价值；业务逻辑位于可测试层；依赖方向单向；复杂度、函数和文件超限必须拆分或例外；公共契约必须版本化、迁移和可回滚；不得吞错。
- `API-001` 至 `API-006`：API 定义契约、鉴权、分页、排序、限流和兼容策略；写操作明确幂等性；异步集成处理重复、乱序、重试和死信；调用第三方前确认授权和数据边界。

## 4. 前端与测试

- `UI-001` 至 `UI-007`：客户端不承担最终授权；异步流程具有完整状态；表单双层校验；关键旅程满足基本无障碍；敏感数据不进入 URL、浏览器存储或前端日志；高风险操作二次确认。
- `TEST-001` 至 `TEST-009`：行为变更覆盖成功、边界和失败；单测确定且隔离；集成/E2E 使用团队拥有的真实隔离组件；关键旅程同时验证可见结果与后端状态；变更行覆盖率 80%，关键安全模块 90%。

## 5. 供应链、运维与治理

- `DEP-001` 至 `DEP-008`：依赖与锁文件受控；高危漏洞阻断；构建可复现；制品使用不可变标识；容器适用时非 root、最小化且不含秘密。
- `OPS-001` 至 `OPS-007`：发布有负责人、制品、监控、验证窗口和回滚；配置分离；高风险发布可回滚；服务可观测；安全事件停止相关变更。
- `DOC-001` 至 `DOC-007`：状态与证据一致；变更同步文档；决策、审批和例外可追溯；评审覆盖安全和回滚；维护读写触发矩阵。
- `AI-001` 至 `AI-008`：Agent 变更前说明范围与验证；网络可达不等于授权；保留用户改动；读取实际输出后才可报告成功；重复问题必须回灌为规则或检查。
