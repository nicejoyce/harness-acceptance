# 文档读写触发矩阵

| 文档/记录 | 必须读取的时机 | 必须更新的时机 | 责任模块 |
|---|---|---|---|
| 项目画像 | 每次变更开始、运行项目命令前 | 工具链、环境、负责人或审批边界变化 | 平台/Agent |
| 需求记录 | 新功能、范围不明确、验收前 | 新需求、范围或状态变化 | 产品/工程 |
| Bug 台账 | 收到缺陷报告、开始修复前、验证前 | 缺陷状态、影响、根因、负责人、修复或验证证据变化 | 工程/QA |
| 设计记录 | 非平凡行为、接口或架构变化前 | 设计、数据流或失败策略变化 | 架构 |
| ADR | 技术选型、继承例外、重大权衡前 | 决策接受、替代或废弃 | 架构 |
| 风险评估 | 数据、外部服务、认证、Schema、CI、部署变更前 | 风险、补偿控制或审批变化 | 安全/负责人 |
| 测试计划 | 行为、安全、权限和关键旅程变化前 | 测试策略、证据或缺口变化 | QA/模块所有者 |
| 评审记录 | 合并前 | 质量门禁、例外或回滚变化 | 评审人 |
| 发布记录 | 发布前 | 制品、监控、验证窗口或回滚变化 | 发布负责人 |
| 事件记录 | 疑似泄露、未授权访问或重大故障时 | 事件状态、时间线和纠正措施变化 | 事件总指挥 |
| 项目进度 | 项目例会、交付规划、里程碑决策和发布就绪度评审 | 阶段、里程碑、整体状态、预测、重大风险、阻塞项、依赖或发布就绪度变化；每个报告周期至少一次 | 交付负责人 |

普通缺陷使用 Bug 台账；安全、数据或重大运行事件使用事件记录，两者同时适用时必须互相关联。命令失效、规则冲突或项目事实变化必须在同一变更中更新相关文档。未完成验证不得更新为已完成状态。
